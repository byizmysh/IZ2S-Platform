Menu pipelines use DISABLE_OPTIMIZATION to reduce first-use compilation, plus a
persistent Vulkan cache at /iz2s/cache/menu-vulkan.bin. Applications retain their
own pipeline settings. The cache is optional, bounded and checked against IZA
SHA256, Vulkan UUID/vendor/device/driver, native cache header and payload SHA256.
A cache miss uses normal creation, without relaxing SD or runtime verification.
Cache serialization and /iz2s/launcher-startup.json happen once, two seconds after
the first presented frame. The report scope is native_menu, not the Civ7 exploit
or the entire R-to-menu interval. cacheAccepted is distinct from actual driver
pipelineCacheHits. Measure first and second launches on the console separately.

First-frame status I/O is deferred; clock updates use monotonic extrapolation.
NRO versions reuse the validated NACP read during catalog discovery; launching
still validates the NRO header/size. App receipts are avoided for bundled IZA
headers whose exact SHA256 is in the generated version table.
