# IZ2S 0.3.2 validation

Recorded on 25 November 2026. PC installation, archive checks and console observations are separate results.

## First installation on Linux x64

The complete Linux archive was extracted into a fresh directory and installed with the documented command, `sh ./install.sh --launch`. The ordinary desktop installation used a regular user, the real host network and Wi-Fi devices, and no container or preview mode. It completed on the first attempt with exit code 0. No application files were edited, no keys or settings were copied, and no dependencies were installed manually. Existing host dependencies were available in this test.

The installer opened the panel, and the user confirmed that its window and interface worked. The menu and desktop shortcuts pointed to the new installation. Installed file hashes matched the archive inventory, and the panel's SD download matched the prepared SD ZIP byte for byte on this host. The initial PC preparation still correctly required the user's own keys and capability checks.

A separate fresh Ubuntu 24.04.5 x64 container began without Node.js, Python, curl, OpenSSH or Pillow. The same documented installer automatically prepared its dependencies and started the HTTP panel on its first attempt. This minimal container had no desktop browser or `xdg-open`, so it did not demonstrate a visible window. Dependency installation in that test ran as root; it did not exercise an interactive non-root package-manager password prompt.

The subsequent publication refresh changes documentation, the release-status field and the matching inventories. It preserves the installer code, application code, native binaries and SD archive from these tests.

## Archive and runtime checks

- Source and Linux inventories, native resource bindings, application exports, compatibility checks and archive readback are verified.
- The SD package contains 188 entries under `iz2s/`, with four applications, companion assets, manifests, licenses and the tested IZPS2 persistence-disable flag.
- A freshly extracted Linux archive can serve the SD download in preview without enabling console actions.
- FAQ content is provided in English, Russian, Simplified Chinese and Spanish. This release contains no Windows installer or Windows host binary.

ZIP compression is runtime-dependent: the panel-generated SD ZIP in the Node.js 24 container had a different archive hash from the Node.js 22 packaging host. All 188 extracted files, including the manifests, were byte-identical and passed CRC checks. Published archive checksums identify the uploaded release assets; compare extracted manifest entries when checking a ZIP generated by a different runtime.

## Console observations

The native menu and IZPS2 engine are the same bytes used in the successful diagnostic test. With `vu-split-persist-off.flag` installed, one instrumented IZPS2 exit closed all 52 tracked files and returned to the menu without outstanding tracked worker/image state. The user also repeated IZtwiNS2 launch/exit and Civilization VII HOME -> X closure without error 2162-0002.

The flag disables optional IZPS2 VU disk persistence, not ordinary JIT execution, game saves or the menu startup cache. No controlled FPS comparison was performed. These observations support shipping the mitigation; they do not establish the exact shared-process fault mechanism or prove that every crash is resolved.
